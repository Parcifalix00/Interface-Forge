# Brand lock

A brand lock is a decision register, not an engine that automatically makes files immutable. Reuse the project's existing register when one exists. The JSON template is optional and transitions still require agent and user review.

Each slot has an ID, revision, status (`unresolved`, `proposed`, `approved`, or `superseded`), value or path, source, and approval reference. An asset hash identifies a version. It does not establish usage rights.

Typical slots include name, logo, palette, typography, iconography, shape/spacing rules, and prohibited treatments. If the user declares an element official, preserve that declaration and source. Do not change it to fit a proposal.

Approval must refer to the exact revision. Do not reuse an approval after a material change. Do not request a new brand selection for implementation details that were already authorized.

Derivatives list the slots and revisions they use. Changing a palette or logo requires review only of relevant derivatives. Preserve history and the previous version. Do not remove the asset currently in use until an approved replacement exists.
